# Agent rules

- Four apps in `apps/` (`customer`, `admin`, `platform`, `site`), one shared package in `packages/shared/`. Do not introduce another app or move code outside this structure without asking. `site` is the static marketing page: no API calls, no auth, no Firebase.
- Tailwind v4 — there is no `tailwind.config.ts`. The `@theme` block lives in [`packages/shared/src/tokens/tokens.css`](packages/shared/src/tokens/tokens.css). Tokens are added there, not in JS config.
- Backend is FastAPI in a separate repo. The contract is [`docs/openapi.yaml`](docs/openapi.yaml). When you change request/response shapes in `packages/shared/src/types/`, update the spec in the same change.
- Customer app must stay unauthenticated. Admin app authenticates by email/password (`POST /auth/login`) and sends a short-lived JWT as `Authorization: Bearer`, with a refresh token handled by the shared `client.ts` (single-flight refresh on 401). The platform app sends an `x-platform-token` header, also attached by `client.ts`. There are no session cookies; the customer app carries no credentials at all.
- FCM is admin-only. Do not import Firebase into `apps/customer`.
- Subscription plans differ by **capacity, not capability** — every tier gets the whole product. Two axes only: monthly order volume (Lite 10,000, everyone else uncapped) and locations (Lite and Standard 1, Pro uncapped). Staff accounts and tables are unlimited on every tier. Do not gate a feature behind a tier, and do not reintroduce a staff or table cap — both were proposed and dropped, because they bite during service. Caps live in [`packages/shared/src/utils/tiers.ts`](packages/shared/src/utils/tiers.ts); the rationale is in [`docs/plans.md`](docs/plans.md).
- Color usage is governed by [`docs/color-usage.md`](docs/color-usage.md) — the canonical surface/elevation rule for all three apps, now Material 3 (DS v3, solved from the seed in HCT). In short — **lighter is higher**. Page: `bg-surface` (grey `#F2F2F2`) — and the customer/platform top bars; admin top nav (only) plus card/drawer/rail: `bg-surface-container-low` (white); a well set into a card, or a field: `bg-surface-container` (the page tone, so it reads as inset); a neutral control on a card (quiet button, round icon button, neutral badge): `bg-surface-container-high`, hover `-highest`; dialog/menu/sheet/floating bar: `bg-surface-overlay` (white + shadow). Never a neutral fill one step from its parent. Chips are outlined at rest and take `bg-primary`/`text-on-primary` when selected — the system-wide selected state, shared with the nav and the selected list row. Filled buttons use the seed `bg-primary` #F56500 with a **16px semibold** white label — white is 3.11:1 on it, which is AA for large text only, so body-size brand text uses `text-primary-label` (P40, 6.16:1). Neutrals are a **true neutral** — black-to-white in OKLCH at zero chroma, so `R=G=B` and they are literally colourless. Fixed and shared by every tenant, so the seed only ever reaches accents and the ramp works under any brand palette. Steps are named by OKLCH lightness (`grey-64` is L=64%). Never hardcode hex or use a raw palette step for a surface.
